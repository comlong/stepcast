# Regression tests

```bat
.venv\Scripts\python.exe -X utf8 tests\run_all.py           :: the regular 24 groups, about 10 minutes
.venv\Scripts\python.exe -X utf8 tests\run_all.py -k reveal :: only tests whose name contains "reveal"
.venv\Scripts\python.exe -X utf8 tests\run_all.py --lint    :: run ruff first (.venv\Scripts\pip install ruff)
.venv\Scripts\python.exe -X utf8 tests\run_all.py --exe     :: also test dist\StepCast (run build_exe.bat first)
.venv\Scripts\python.exe -X utf8 tests\run_all.py --ppt     :: also test real PowerPoint (skipped while PowerPoint is open)
```

Each group prints pass / fail; the full output is in `tests/_work/run/<test name>.log`.

## Rules

- **Never touch the user's data:** every test uses its own data folder (`VT_DATA_DIR`) and its own `config.json` (by changing `config.CONFIG_PATH`) under `tests/_work/run/`; the user's `projects/` and `config.json` are never read or written.
- **Never spend money:** LLMs are replaced by fake clients, cloud voice services by fake keys and fake endpoints; no real requests are sent.
- **Leave PowerPoint alone:** every test except `test_reveal_ppt` sets `VT_DISABLE_POWERPOINT=1`; `test_reveal_ppt` only runs while PowerPoint is closed and quits only the instance it started.
- For a complete recorded project use `fixtures_build.make_capture_project(data_dir)`: a fake admin page drawn with PIL plus tones generated by ffmpeg — 8 steps, about 70 seconds, no real project involved.

## Layout

| Path | Content | Committed |
|---|---|---|
| `test_*.py` | The test groups; run as `python -X utf8 test_x.py <work dir>` | yes |
| `run_all.py` | Runs everything | yes |
| `fixtures/` | Generic test data: short audio, test-pattern videos, a few simple PPT / PDF files. `vid/make_video_decks.py` regenerates the two decks with embedded videos | yes |
| `fixtures_build.py` | Builds the synthetic recorded project | yes |
| `lang_samples.py` | One sample sentence per language for language detection tests | yes |
| `stab_server.py` | The real server process started by `test_stability` | yes |
| `ui_server.py`, `ui_seed*.py`, `demo_sub2.py` | Test server for looking at the UI by hand (port 8770, data in `_work/ui_data`; `ui-test` in `.claude/launch.json`) and a second-subtitle demo | yes |
| `private/` | Company-internal material (a real deck and the test section that uses it); `test_reveal_ppt` includes it when present | **no** |
| `_work/` | Working folder at run time | no |

## Adding a test

Start like the existing files: set `VT_DATA_DIR`, put `ROOT` on `sys.path`, point `config.CONFIG_PATH` at the work folder, then import the backend. Report each check with `check(name, condition, detail)` and finish with the summary line. `run_all.py` treats `[FAIL]`, `Traceback` and the failure summary in the output as a failure. Add the new test's name to `TESTS` in `run_all.py`.
